# CLAUDE.md: motion-rs

State and invariants only; the reasoning is in `docs/design.md`.

- One op vocabulary (`motion_core::Backend`), one reference. A new op means:
  the CPU implementation, the WGSL kernel and a case in `motion-check`, all
  in the same change. The CPU backend is ground truth; a GPU backend is
  trusted on a card only after `motion check --backend <b>` passes there.
  Nothing has run on a real GPU yet: WebGPU has passed its checks only on
  lavapipe (mesa's CPU Vulkan driver) in CI and in the authoring container.
- Two models, two contracts, both held to PyTorch fixtures:
  Kimodo (`motion-kimodo`: nv-tlabs/kimodo, two-stage transformer denoiser,
  DDIM over a 1000-step cosine schedule, separated CFG, SOMA-30 smooth-root
  representation, output on SOMA-77) and MotionBricks (`motion-bricks`:
  NVlabs/motionbricks, root module + masked pose module + VQ-VAE decoder,
  SOMA and Unitree G1 rigs, the ONNX tensor interface of the release).
  `scripts/reference/*_fixtures.py` regenerate the fixtures from the upstream
  Python with the released weights; the tests under `crates/*/tests` state
  the tolerance each fixture holds.
- Weight keys are the PyTorch state-dict names; every model reads every key
  it needs by exact name and shape (`WeightSource::get`), a missing key is an
  error, never a default. Checkpoints: Kimodo HF trees (`config.yaml`,
  `model.safetensors`, `stats/motion/{global_root,local_root,body}`),
  MotionBricks HF trees (`soma/…/model-step=1500000.safetensors` ×3,
  `g1/out/…/model-step=2000000.safetensors` ×3, `stats/motion/{mean,std}.npy`).
- Skeleton assets are embedded (`motion_core::assets`, generated by
  `scripts/assets/generate.py` from the upstream repos, Apache-2.0); the
  NVIDIA sample clips (`assets/motions/**` upstream) are evaluation-only and
  are never committed here.
- The Kimodo text encoder (LLM2Vec over Meta-Llama-3-8B-Instruct) is ported
  but the base weights are gated: the real encoder has not run here. Kimodo
  runs from precomputed embeddings (`motion encode` writes them) or with an
  empty prompt (zero text features, constraints only).
- No speed claim without a measurement on named hardware recorded under
  `docs/runs/`. The only record is CPU-reference timing in the authoring
  container; there are no GPU numbers.
- `motion serve` (the Motion Studio) serves `web/studio.html` via
  `include_str!`; its JSON API is documented in `docs/studio.md` and the page
  is its only client, so change both together.
- Sub-agents never `git commit`; the coordinating session commits and opens
  the PR.
