# motion-rs design

Rust inference for two NVIDIA motion models, built the way fastwan-rs and
h3-rs were built: one small fused op vocabulary, a CPU reference that defines
every op, GPU backends checked against it, host-side glue for everything that
is not a tensor op, and PyTorch parity fixtures generated from the released
weights.

## The models

| | Kimodo (`motion-kimodo`) | MotionBricks (`motion-bricks`) |
|---|---|---|
| upstream | [nv-tlabs/kimodo](https://github.com/nv-tlabs/kimodo), Kimodo-SOMA-RP-v1.2 (282 M) | [NVlabs/motionbricks](https://github.com/NVlabs/motionbricks), MotionBricks-SOMA-RP-v1 (200 M), -G1-RP-v1 |
| task | text + kinematic constraints → 3-D motion, up to 10 s at 30 fps | four context poses + 1–4 target poses → 0.6–1.9 s transition, chained in real time |
| generator | explicit diffusion over a 369-d per-frame representation, DDIM (η = 0) over a 1000-step cosine schedule, classifier-free guidance with separate text / constraint weights | root module (duration class + root path), masked pose transformer (5 codebook heads × 16 codes for SOMA, 8 × 10 for G1; one argmax pass), VQ-VAE decoder conditioned on the root path and the target poses |
| networks | two 16-layer post-norm `TransformerEncoder`s (d 1024, ff 2048, 8 heads, GELU): root stage (5-d global root), body stage (364-d) | pose: 16 layers, d 1024, 16 heads, ReLU, ff 2048; root: 6 + 2 (SOMA) / 3 + 3 (G1) layers, d 512; decoder: 1-D conv U-Net (width 512, depth 4, dilations 1/3/9/27, two ×2 upsamples) |
| conditioning | text as one pooled 4096-d LLM2Vec embedding padded to 50 tokens, timestep token, heading token; constraints overwrite features and a mask is concatenated to the input | masks per slot (`has_*`), learnable "no value" embeddings, allowed token counts |
| skeleton | SOMA 30 predicted, SOMA 77 output (relaxed-hand rest pose) | SOMA 30 (T-pose change capture ↔ standard), G1 29 DoF + free root |

## The op vocabulary

`motion_core::Backend`: `linear` (bias + activation epilogue), `layer_norm`,
`rms_norm`, `attention` (packed `[q|k|v]` rows, grouped KV heads, key mask),
`rope`, `swiglu`, `conv1d` (stride / pad / dilation, nearest ×2 upsample
fused, bias, activation, residual), `unary`, `binary`, `axpby`, `mask_time`,
plus `copy` / `fill`. Thirteen ops cover both motion models and the LLM2Vec
Llama encoder. Everything else is host code on small tensors: feature
packing, normalisation statistics, the DDIM update, token sampling, the
global ↔ local root conversions, forward kinematics, constraint masks.

`motion-nn` holds the PyTorch-shaped blocks on top of the ops
(`nn.Linear`, `nn.LayerNorm`, the post-norm `TransformerEncoderLayer`,
MLP chains, the sinusoidal table) so both model crates read the same
state-dict keys the same way.

## What runs where

| piece | where |
|---|---|
| Kimodo denoiser (both stages, 3-way CFG batch) | backend |
| Kimodo motion representation, DDIM, constraints, FK, smooth root (ADMM) | host |
| MotionBricks root / pose transformers, VQ-VAE decoder | backend |
| MotionBricks feature encode / decode, token sampling, endpoint correction, chaining | host |
| LLM2Vec Llama-3-8B (bidirectional) | backend, streamed one layer at a time from the mmapped shards |

## Verification

- `cargo test --workspace`: op identities on the CPU reference, the WebGPU
  conformance suite on lavapipe, each model on tiny random-weight fixtures
  generated by the upstream PyTorch code (so CI needs no download), and
  `#[ignore]`d tests on the released weights (`MOTION_KIMODO_DIR`,
  `MOTION_BRICKS_DIR`).
- The fixture scripts and the tolerances they hold are in each crate's doc
  (`docs/kimodo.md`, `docs/motionbricks.md`, `docs/text-encoder.md`,
  `docs/backends.md`).
